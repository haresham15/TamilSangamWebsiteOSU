## 2025-02-28 - [JSON-LD Cross-Site Scripting (XSS)]
**Vulnerability:** Found multiple instances where structured data (JSON-LD) was directly serialized using `JSON.stringify(data)` and injected via `dangerouslySetInnerHTML`. An attacker could theoretically inject a `</script>` tag inside user-provided JSON-LD data and execute arbitrary JavaScript.
**Learning:** React's standard `dangerouslySetInnerHTML` for `<script type="application/ld+json">` is vulnerable to XSS if the JSON payload is not escaped, because the HTML parser sees the closing `</script>` string before the JSON parser finishes.
**Prevention:** Always escape the `<` character in JSON payload strings when injecting them into script tags. Using a pattern like `JSON.stringify(data).replace(/</g, '\\u003c')` securely neutralizes the attack vector while preserving valid JSON-LD structure.
## 2026-10-21 - [High] Prevent XSS String Breakout in JSON-LD Injection
**Vulnerability:** The `CalendarEventJsonLd` component injected structured JSON-LD data into a `<script>` tag using `dangerouslySetInnerHTML` without escaping the `<` character. If event metadata (e.g. title, description, location) contained `</script>`, an attacker could break out of the script context and execute arbitrary JavaScript.
**Learning:** React's built-in XSS protection does not apply to `dangerouslySetInnerHTML`. When embedding JSON within `<script>` tags, simply using `JSON.stringify` is insufficient. The serialized string must be sanitized specifically to neutralize HTML tags.
**Prevention:** Always escape the `<` character when stringifying JSON data for script injection: `JSON.stringify(data).replace(/</g, '\\u003c')`. This specific pattern is codified in the `safeJsonLd` utility function found elsewhere in the codebase and should be used universally.
